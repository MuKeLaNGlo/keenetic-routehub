# Политика сети и устройств

RouteHub связывает устройства с политиками по MAC и подтверждённому адресу IPv4. Проверка маршрута показывает расчётное правило и результаты отдельных сетевых проб.

## Приоритеты RouteHub

| Режим | Порядок |
| --- | --- |
| Устройство без отдельной политики | Глобальные правила сверху вниз, затем глобальный маршрут по умолчанию. |
| `inherit` | Условия устройства сверху вниз, затем глобальные условия и глобальный маршрут по умолчанию. |
| `override` | Условия устройства сверху вниз, затем явно заданный маршрут устройства по умолчанию. |

Первое совпадение завершает выбор. Пустой глобальный `defaultTarget` означает `direct` и сохраняет поведение ранних конфигураций. Новое устройство наследует глобальные настройки при подключении к охваченному сегменту. Применённую политику устройства можно увидеть в объяснении маршрута по полям `scope` и `deviceMAC`. Домен по умолчанию включает поддомены. Поле `exact: true` ограничивает совпадение самим доменом и компилируется как `full:`.

```json
{
  "defaultTarget": "direct",
  "rules": [
    {"name": "Видео", "domain": "video.example", "target": "vpn"}
  ],
  "devices": [
    {
      "mac": "02:00:00:00:00:20",
      "label": "Ноутбук",
      "addresses": ["192.168.50.20"],
      "mode": "inherit",
      "rules": [
        {"name": "Видео на ноутбуке", "domain": "video.example", "target": "direct"}
      ]
    },
    {
      "mac": "02:00:00:00:00:21",
      "label": "Тестовое устройство",
      "addresses": ["192.168.50.21"],
      "mode": "override",
      "defaultTarget": "vpn"
    }
  ]
}
```

Здесь `vpn` обозначает ID существующего профиля. Условия без совпадения для ноутбука идут по общей политике. У тестового устройства весь оставшийся трафик идёт через `vpn`.

## Интеграция

- [Модуль политики](../../module-rust/crates/policy/) нормализует правила, сопоставляет профили с протоколами и фиксирует порядок.
- При сборке правил Xray личная политика ограничивается адресом источника `/32` и входом прозрачного перехвата. Локальный SOCKS использует общие правила. [Условия маршрута Xray](https://xtls.github.io/en/config/routing.html)
- `POST /api/evaluate` принимает назначение, транспорт и порт. Поля `clientMAC` и `clientIP` выбирают область проверки. Когда известен IP назначения, передайте его в `targetIP` для учёта CIDR.
- `GET /api/devices` показывает адреса, режим и причину, по которой персональная политика не активна.

## Привязка адресов

Записывайте IPv4 устройства после назначения ему постоянного DHCP-адреса в Keenetic. Для Wi‑Fi используйте стабильный MAC именно для этой сети. Модуль проверяет формат MAC, дубли, границы подсети, адрес сети, шлюз и broadcast. IPv6 сейчас остаётся вне персональных правил, пока сам перехват поддерживает только IPv4. [Список клиентов Keenetic](https://support.keenetic.com/hopper/kn-3811/en/14007-client-lists.html), [регистрация устройств](https://support.keenetic.com/hopper/kn-3811/en/14008-connected-devices-registration.html).

Без инвентаря компилятор использует постоянные привязки, заявленные администратором. При наличии инвентаря каждый адрес должен иметь ровно одного владельца в снимке и совпадающее подтверждение `Fixed`. Запись из ARP, таблицы соседей или динамической аренды может выявить конфликт, но сама не подтверждает постоянную привязку. Пустой подтверждённый снимок деактивирует персональные правила. При этом действует глобальная политика.

Адаптер читает локальный список клиентов через `/bin/ndmc -c 'show ip hotspot'`, настройки DHCP через `show running-config | grep "^ip dhcp host "` и таблицу аренд через `show ip dhcp bindings`. Фильтр выполняется внутри KeeneticOS. Для подтверждения постоянного адреса запись `ip dhcp host <MAC> <IPv4>` должна совпасть с записью того же MAC и IPv4 в таблице DHCP со сроком `infinity`. Это учитывает случай, когда настройка содержит IP вне действующих пулов. Адаптер дополняет сведения наблюдениями `/proc/net/arp`. Эти наблюдения могут выявить конфликт, а постоянный адрес подтверждается только данными двух команд DHCP. Адаптер работает с локальным CLI прошивки и не требует отдельной аутентификации из приложения. [Фиксированный IP клиента](https://support.keenetic.com/hopper/kn-3811/en/14008-connected-devices-registration.html), [справочник CLI KeeneticOS 5.1](https://storage.googleapis.com/docs.help.keenetic.com/cli/5.1/en/cli_manual_kn-1812.pdf).

Пока действует предыдущая конфигурация Xray, изменение DHCP-привязки требует повторной проверки и применения правил. Защита от подмены IPv4 требует отдельной проверки MAC на уровне LAN.

## Проверка

Команда `cargo test -p routehub-policy` из `module-rust/` проверяет порядок правил, режимы, валидацию, конфликты адресов и разбор инвентаря. Фактический перехват проверяйте с устройством в LAN.
