# Прозрачный перехват IPv4

На KN‑3811 этот режим включается отдельно после проверки явного SOCKS. Для первого испытания добавьте `"transparent":{"interface":"br0","source":"192.168.50.64/32","port":18954}` с фактическим Linux-именем интерфейса LAN и адресом выделенного клиента. Сохраните отдельный доступ к администрированию. Во время обычной работы SOCKS секция не применяется. Проверка наличия StealthSurf, занятых таблиц и меток работает при старте перехвата.

RouteHub поднимает Xray, затем добавляет собственный переход IP mangle PREROUTING в `RH_TPROXY` для одного настроенного источника. Правила направляют TCP и UDP на прозрачный вход Xray через метку `0x52000/0xff000` и отдельную таблицу `7354`. Локальные адреса и сети из списка исключений, порты DNS и IPv6 идут своим обычным путём.

На Keenetic можно выбрать `"mode":"redirect-tcp"` в секции `transparent`. Этот режим использует IPv4 DNAT для TCP. UDP, IPv6, локальные адреса и порт DNS идут штатным путём. `panelHost` должен быть частным IPv4-адресом выбранного LAN-интерфейса, а `source` — подсетью внутри `panelNetwork`. Можно указать отдельный клиент с префиксом `/32`. Перед запуском Xray RouteHub ставит входной фильтр. Он пропускает на порт Xray только перенаправленные TCP-соединения из выбранной подсети и с нужного интерфейса. KeeneticOS восстанавливает эти правила в таблицах `nat` и `filter`.

При остановке сначала удаляется переход в цепочку, затем её правила и маршрут, затем останавливается Xray. При аварийной остановке helper следит за PID и временем запуска процесса. Хук KeeneticOS вызывает быстрое восстановление IPv4 mangle только для работающего экземпляра.

Для одноразового запуска в согласованное окно предусмотрен флаг `routehub serve -allow-lan`. Для ручного запуска через init-скрипт предусмотрен файл-разрешение `/opt/etc/routehub/allow-lan`. Установленный пакет запускается автоматически только при наличии отдельного файла `autostart`.

Оба режима требуют совместимые `iptables` и `ip`. Для Entware команды предоставляют пакеты `iptables` и `ip-full`. Режим `tproxy` требует поддержку TPROXY в ядре, а `redirect-tcp` — DNAT и conntrack. При наличии команды `conntrack` RouteHub удаляет связанные записи NAT при деактивации.
Сначала проверьте базовый трафик и отказ одного профиля на выделенном клиенте. Пакет использует `--queue-bypass` в адаптере Zapret, поэтому при остановке обработчика его маркированный WAN-трафик идёт напрямую.
